## 优化顺序

### 1. 报告可信度：结构存在与证据支持分开

位置：`src/modules/product-rnd/deep-report.ts`、`src/components/executive-report-role-based.tsx`。

已复现：规格行只有 name/value/FACT、没有 evidenceRef，BOM 行有金额、没有 sourceRef，也会让两节 ready=true。视图芯片将 ready 解释为“有实数据”。BOM 明细已有无来源警告，但摘要状态与明细的可信度口径不一致。此复现仅在纯函数边界，未证明真实生产报告已写入无源数字。

建议：保留不完整资料，增加来源解析与核验状态；有字段、可追溯、已核验分别表达。来源引用需校验同组织/同项目、实际存在及报价适用条件。FACT 标记不能单独成为核验依据。金额还需单位、币种、数量和计算一致性校验。

验收：无来源、假引用、跨组织引用、过期报价、单位冲突不得显示为可用于决策；合法引用可定位原始资料。人工假设明确标注，不与真实报价混用。

### 2. 打通一条真实资料消费链

位置：`src/modules/product-rnd/executor-strategies.ts:353`、`:376`。

已确认：配方和 BOM 策略无条件返回 honestBlocked，没有读取输入并产出结果的分支。仅新增上传入口无法解除此阻断。

建议首批做报价/BOM：原始文件 → 结构化草稿 → 人工确认关键字段 → 保存来源锚点 → 确定性成本计算 → 报告。复用现有证据和成本引擎，模型用于提取与解释。配方专业决策另设资料和审核要求。

验收：用一份真实报价完成上传、缺字段追问、补齐、BOM、毛利比较、报告导出；修改报价后生成新版本且可复算。

### 3. 恢复默认质量门禁的可重复性

位置：`eslint.config.mjs`、`scripts/run-test.ts`、`package.json`。

已确认：lint 忽略列表遗漏 `.next-fixed`、`.next-local-test`；全量扫描因此误报生成文件。报告链接引入 server-only 后，默认测试子进程没有 React server condition，R3 在运行断言前退出。

建议：统一构建目录忽略规则；对实际需要服务端条件的测试统一入口，避免依赖操作者记住环境变量。同时检查纯客户端测试是否需要保留正常 React 条件。按纯函数、隔离数据库、浏览器真实操作分层。

验收：干净检出与包含历史构建目录的工作区，默认 lint 均通过；默认 npm R3 命令实际运行六项断言。

### 4. UNKNOWN 转成用户能执行的补资料动作

位置：`src/modules/product-rnd/deep-report.ts` 的 DEEP_SECTION_META。

已确认：缺口文字包含 formulation_agent、result.deep.spec、specialist 和“本批未接生产者”等内部描述。用户无法据此完成补齐。

建议：使用“缺少供应商报价，请上传含规格、MOQ 和日期的文件”等业务语言；接入上传、补字段、指派责任人和完成后继续执行。区分缺少用户资料与系统尚未实现，后一类应说明能力边界。

验收：用户从缺口卡即可补齐所需输入，原任务继续执行，已成功步骤不重复调用。

### 5. 首页查询做有界批量读取

位置：`src/modules/muse/read-model.ts:169-209`。

已确认：loadAttention 遍历最多 12 个任务，每个符合条件的任务分别 await message.findUnique 和 message.count，最多产生 24 次串行消息查询。未测得实际延迟。

建议：批量获取结果消息与后续用户消息，保持组织/用户范围；长事件流使用状态快照或正确分页。当前 askRows 总 take=1000 也需检查长会话是否截断回答状态。

验收：用较多已结束任务比较查询数和首页延迟；数据增大时未回答数正确，不能因截断把已回答问题重新显示为待处理。

### 6. 角色逻辑和交付版本收敛

已确认：前后端各有角色类型、关键词与切换规则；当前未提交差异中大量是换行变化，忽略行尾空白后多数文件无实质变化。

建议：将共同角色规则放 shared，前后端只保留各自上下文适配。功能变更和换行统一分别交付。路线图记录验收对应提交及工作区状态；继续保留后台能力，逐步将普通用户导航收敛到对话、产品、项目、资料与设置。

验收：同一句明确角色切换指令前后端结果一致；实际修改能清晰审阅；验收结果可定位具体版本。

## 建议执行批次

1. 门禁与报告状态口径修复：投入小，先让检查和可信度表达稳定。
2. 真实报价到 BOM 到报告：投入中等，直接验证用户价值。
3. 补资料交互与任务恢复：投入中等，减少反复人工操作。
4. 首页批量读取、角色共用规则、导航及版本收敛：按实际使用反馈推进。

继续使用现有 MissionMetrics/模型账本记录验收通过率、人工纠正、重跑、交付耗时与实际调用次数。成本估算与供应商真实账单分开。
