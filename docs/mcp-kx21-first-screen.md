## 1. 用户视角

1. **登录页**：左侧表单、右侧一句话定位「交代一句话，Kern 交回一份能直接用的办公成果。过程看得见，关键动作先问你。」；
   去掉居中卡片、分割线、「AI PRODUCT OS」副标题和密码框里的一串圆点；背景与 Muse 是同一张画布 + 光晕；窄屏（≤ 820px）只保留表单。
2. **Muse 空态**：问候与示例整体贴近输入坞（示例卡到输入坞 229px → 56px），对话开始后内容原地上移，没有位置跳变；
   「交给 Kern」小标题、问候副文、快捷键提示、输入框占位符的对比度都 ≥ 4.5:1；手机上输入坞控件 ≥ 44px。
3. **示例任务**换成三个能真正跑起来、且有意义的任务（见 §3）：评估一个新品方向 / 做一份竞品调研 / 排查一个方向的合规风险。

## 3. 示例任务与路由（验证记录）

意图路由是**关键词优先**的（`assistant-runtime/router.ts`），而且判断的是**整条消息**，所以示例提示的措辞直接决定它走哪条路径。
用真实函数（`routeIntent` + `buildKernCollaborationPlanShadow` + `decideMissionLaunch`）逐条验证：

| 示例 | 意图 | 协作模式 | 结果 |
|---|---|---|---|
| 评估一个新品方向 | NEW_PRODUCT_INTAKE | — | 起任务：新品全流程 9 环节（市场、合规、经济性、机会、验证、上市、红队、QA、综合） |
| 做一份竞品调研 | KNOWLEDGE_SEARCH（被任务取代） | PAIR：研究 + 产品 | 起任务：研究 → 产品 → 综合 |
| 排查一个方向的合规风险 | PRODUCT_STATUS（被任务取代） | PAIR：研究 + 合规，命中高风险词，QA 必需 | 起任务：研究 → 合规 → 独立 QA → 综合 |

起任务后都会先出「我拟的计划」和任务契约卡，用户点开始才执行（KX-72）。

淘汰的候选（以及原因，实测）：

- 旧「汇总产品进展」：命中「产品」→ `PRODUCT_STATUS`，只回一句「组织内共 N 个产品，生命周期分布…」，并不会「找出阻塞和下一步」。
- 旧「交代一项工作」（如整理本周周报）：「本周」命中 `WORKSPACE_STATUS`，回的是状态统计，不是周报。
- 整理会议纪要：粘贴的记录里常见「决定 / 项目 / 任务」，整条消息会被路由成待决事项 / 状态查询。
- 挑战一个判断：`CHALLENGE_THESIS` 要求会话已绑定产品，首屏会话没有，会直接回「当前会话未绑定产品」。

**以后写首屏示例的规则**：提示里避开 决策 / 拍板 / 决定 / 审批、待办 / 本周 / 今天 / 进度 / 任务 / 项目、复核 / 证伪 / 反方、本机 / 终端 / 路径 等词，除非就是想走那条路径；
想起「任务」就要让命中的专家 ≥ 2 个（或是新品目标）。

## 4. 决定与取舍

- **贴底而不是居中**：输入坞位置不动，对话开始后没有位置跳变；「输入坞居中」（方案 A / C）留给 KX-23 的 composer 变形。
- **办公类示例（会议纪要 / 周报）暂未上首屏**：要先解决「粘贴长文本被关键词路由截胡」，已记入需求池 R-03。
- **`--k-brand-solid` 只给登录主按钮用**：其他深色主按钮（对话里的发送、分段控件选中态）仍是 3.74:1，想统一时改一处令牌引用即可。
- 侧栏「最近对话」摘要对比度约 2.3:1、顶栏 6 个按钮在手机上偏挤，属 KX-20 外壳，只记录不改。
- 旧 `.hermes-login*` 样式仍在 `globals.css`，已无任何引用，后续清理。
