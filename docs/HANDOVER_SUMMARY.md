## 1. 核心修复与交付成果 (R01 - R10)

1. **会话认证机制与生产防护 (R01)**：
   - 彻底废弃客户端 Cookie 伪造模式，引入服务端基于 DB `Session` 表的可撤销会话，Token 均经 SHA-256 加密存储。
   - 生产模式下误用开发模拟头时直接触发 403 阻断。
2. **多租户数据穿透与权限隔离 (R02)**：
   - 页面与 API 统一使用 `getProjectDetail` 业务授权服务，跨企业读取抛出 404/403，前端人员下拉限制在同企业授权成员内。
3. **证据哈希服务端计算与独立核实 (R03)**：
   - 客户端上传证据由服务器统一下发 SHA-256 哈希，初始为 `UNVERIFIED`。
   - 必须经 PM 独立核实接口流转为 `VERIFIED` 并持久化核实人与核实时间。支持安全受控附件上传。
4. **决策包状态机与冻结快照保护 (R04)**：
   - 严格状态机前置条件：仅 `DRAFT` 或 `CHANGES_REQUESTED` 允许提交；已批准包提交被 409 冲突拦截。
   - 提交时自动生成 `snapshot`，记录提交时刻的完整结构化指纹与要素。
5. **决策并发竞争控制与原子事务 (R05)**：
   - 单个 Prisma `$transaction` 事务内完成前置校验、条件更新 (`status: IN_REVIEW`)、阶段推进、唯一打样准备工作项生成与审计入库。
   - 双并发决策调用时保证严格互斥，败者抛出 HTTP 409 冲突。
6. **权威基准一致性与动态失效机制 (R06)**：
   - 打样门批准前与批准后，动态比对当前权威基线。
   - 一旦项目业务目标、技术约束、产品版本、成果或证据发生任何漂移变更，原打样门批准立即标记为失效，项目展示明确的“待复核”警示。
7. **DEMO 证据阻断与固定产品门禁限制 (R07)**：
   - 实体级别采用正式字段 `isDemo` 与 `EvidenceNature.DEMO/REAL`。
   - 真实项目打样门强行阻断 DEMO 证据；固定产品模式强行阻断执行研发打样门。
8. **固定产品版本绑定与租户校验 (R08)**：
   - 建立完整的产品创建、版本发布与外键持久绑定逻辑。
   - 固定产品必须绑定同公司已确认不可变版本，外键持久存储。
9. **工作项提交批次与成果审查保护 (R09)**：
   - 建立 `WorkSubmission` 独立提交批次。审查仅针对当前提交批次，历史退回批次完整归档，失败回执不降级已验收任务。
10. **独立测试库与破坏性操作硬隔离 (R10)**：
    - 确立 `tests/test-safety.ts` 防御屏障，端口必须为 5433 且库名必须含 `test`。
    - 全面防误伤机制：端口 5432 原有 Python 进程无任何扰动，开发库 `hermes_next_dev` 完整保留。
