### 5.1 全量扫描与两个环境坑

第一次扫描跑到第 26 项就停了：`test:authz`、`test:gate-boundaries-http` 失败，日志都是 `Can't reach database server at 127.0.0.1:5433`。修好环境后重跑，**87 项里 84 项通过**：

| | |
|---|---|
| 通过 | 84 |
| 失败 | 1 —— `test:model-scenarios` |
| 跳过 | 2 —— `test:critical`、`test:sweep`（别名与自身，脚本设计如此） |

两个环境坑（都不是代码问题）：

1. **`.env` 的测试库指向 5433，本机没有实例。** 本机真正在跑的是 `D:/pgsql17` 的 **5432**（库 `hermes_test` / `hermes_dev_guard` / `kern_dev`；78 张表，迁移已到 `20260929150000_memory_v2_topics_correction`）。而 `scripts/acc-server.sh` 第 61 行会 `set -a; . ./.env; set +a`，把 `.env` 的值**覆盖**掉外面 `ci.env` 的 5432——所以这些套件无论怎么设环境变量都会打到 5433。
   处理：备份 `.env` 为 `.env.bak-audit-20260930`，只把 `TEST_DATABASE_URL` / `DEV_DATABASE_GUARD_URL` 指向 5432 的测试库（**没动 `DATABASE_URL`，日常 `npm run dev` 不受影响**）。
2. **Playwright 自带 Chromium 没装**（`chromium-1243` 不存在），`test:ui` / `test:ui-feedback` / `test:mobile-layout` 直接起不来。这三个套件支持 `CHROME_PATH` 覆盖，指向本机已装的 Chrome 即可。

剩下的 `test:model-scenarios` 是 KX-66 的 L2/L3 场景脚本：它按设计要对着**正在运行的 dev 服务器 + 开发库 + Worker** 发真实请求（脚本头部写明了三个前置），当前 dev 栈没起、`DATABASE_URL` 仍指向 5433，所以它跑不通——属于「缺前置」，不是缺陷。
