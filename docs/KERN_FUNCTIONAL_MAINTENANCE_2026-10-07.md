## 本轮修复

1. 工具循环达到上限后，模型仍请求工具时，返回 `OUTPUT_INCOMPLETE:TOOL_LIMIT`，节点受阻。原生围栏、XML、裸工具块与非法参数均遵守同一上限，保留已经执行的记录，不额外增加模型调用。
2. 模型回复为空，或格式整理后没有可显示内容时，返回 `OUTPUT_INCOMPLETE:EMPTY_OUTPUT`。这些回复不再算作成功结果。
3. 任务结果写回原会话失败或进程在两次提交之间退出时，后台会扫描已结束但回执缺失的任务，补写结果。独立的有界补发批次保留活跃任务的执行容量。
4. 回执生成、去重与登记在任务行锁和同一事务中完成，使用最新任务状态；并发补发不会生成多条回执，也不会把已经重跑的旧结果写回来。
5. 补发失败后等待 30 秒再进入后台扫描；修复原会话后可以继续交付，补发不重新执行工具或模型。取消的任务明确回报“已取消”。
6. 受阻回执包含实际步骤说明，汇总节点失败也会告诉用户原因及重跑方式。

没有增加执行引擎或数据库表。新增回归入口 `npm run test:kern-execution-delivery`，已加入 Kern Supervisor CI 配置；本轮未运行在线 CI。

## 秘塔检索与网页读取接入

配置通过权限 `0600` 的 `.env.local` 加载，不把凭据写入代码、数据库或验收报告：

- `KERN_SEARCH_PROVIDER=metaso` 与 `METASO_SEARCH_API_KEY`：固定官方 `/api/v1/search`，实测参数 `q / scope=webpage / size / includeSummary`，将 `webpages` 中的 `title / link / snippet` 转为现有工具结果。
- `KERN_READER_PROVIDER=metaso` 与 `METASO_READER_API_KEY`：固定官方 `/api/v1/reader`，以 `url / format=markdown` 获取 `title / url / markdown`。未配置 reader 时沿用本地安全抓取；关闭网页读取仍由 `KERN_WEB_FETCH=off` 控制。
- 搜索与读取也可共用 `METASO_API_KEY`。问答凭据使用单独的 `METASO_CHAT_API_KEY` 保存。
- `/api/v1/chat/completions` 已使用 `model=fast`、标准 `messages`、非流式模式实际验证，返回回答与 citations。当前研究仍由既有模型调用搜索/读取工具，问答接口没有切换为默认模型，避免把其答案当作已核验网页证据。

接口资料：[秘塔官方 API 实验室](https://metaso.cn/search-api/playground)。三次小请求均 HTTP 200，首次验证约搜索 1.7 秒、读取 0.4 秒、问答 3.5 秒，只代表这次请求。

### 维护边界

秘塔响应限制为 1 MB、30 秒、支持取消、不跟随 API 地址重定向；错误不会回显供应商原文或凭据。Reader 请求和返回网址均经过本地 URL 与 DNS 公网校验；远程服务的连接及内部重定向由供应商控制，不能宣称有本地抓取的 IP 固定保证。本地抓取原有逐跳校验与 IP 固定规则保留。

本轮验证覆盖返回格式、异常/空响应、取消、超量响应、内网地址及私有返回地址拦截。报告生成证明了真实研究交付链路，不代表所有研究结论已经过独立事实核验，也不代表完成了 AKG 医学与法规证据评估。
