# Kern 对话内展示层（Display Layer）规格

状态：✅ grill 3 轮完成，需求 v1 已定（2026-09-26）；下一步实现 PR ①。

## 目标（用户原话）
> 除去 agent 功能效果，可以先把操作和实现的展示功能都完整，
> 实现对话过程中有全面覆盖的展示功能。

我的理解：
- 暂不追求 Agent 的产出质量（开发环境也没有模型）。
- 先把“Kern 在做什么、怎么做、做出了什么、需要你做什么”在对话里**完整、可操作**地展示出来。
- 展示层要能被**真实数据**驱动，也能被**演示数据**驱动。

## 现状盘点（代码事实，2026-09-26）
对话里已有的展示块（`src/app/muse/types.ts` 中的 Block）：
- text（安全 Markdown）
- graph（KernGraph 可视化）
- mission（任务进度卡：节点列表 + 状态）
- evidence（来源与回执）
- plan：类型存在，但**没有真实数据**
- check-in / decision：审批卡，可批准、拒绝、稍后

抽屉：轨迹、来源详情、信任与权限、记忆、拒绝理由、命令面板。

缺口（初判）：
- 任务卡只有节点状态，看不到每个成员实际做了什么：输入、方法、产出、耗时、用的模型。
- 没有产出物（报告、表格、对比、计划）的专门展示与导出。
- 看不到过程中的工具调用、检索、引用来源。
- 用户不能中途干预：暂停、改计划、跳过节点、补充信息。
- 看不到成本或用量、用了哪些记忆、为什么升级给你。
- 没有演示模式：没有模型时，整条链路无法展示。

## Grill 记录
### 第 1 轮 ✅
| 问题 | 决定 |
|---|---|
| 默认展示多细 | **分层**：默认看摘要，一键展开到全透明（工具调用、检索词、引用原文、模型、耗时） |
| 展示放在哪 | **对话里放摘要卡，点开进右侧工作区看全貌**（类似 Artifacts） |
| 没有模型时用什么驱动 | **两者都要**：演示模式（脚本化回放，明确标注“演示数据”）和真实数据共用同一套组件 |
| 中途干预 | **全部要**：暂停/继续/取消；改计划（增删、跳过、重跑某步）；随时补充信息，Kern 自动带进后续步骤 |

### 第 2 轮 ✅
| 问题 | 决定 |
|---|---|
| 工作区产出类型 | **全部**：研究/机会报告（长文 + 引用）、对比表、图表、计划/清单（验证计划、上市排期）、决策卡（推荐 / 反对理由 / 风险） |
| 产出怎么带走 | **一键存入业务对象**（建成产品 / 项目 / 工作项）+ Markdown / PDF 导出 |
| 元信息 | **全部**：成本与额度消耗、这次用到的记忆、为什么派这些成员 / 为什么升级给我 |
| 本阶段范围 | **先把“我想开发一个新产品”这一条做到极致**，其他场景复用组件 |

### 第 3 轮 ✅
| 问题 | 决定 |
|---|---|
| 开场方式 | **先问关键问题 + 展示计划让我确认，再开工**（记忆里已有的信息不再问） |
| 实时性 | **实时流式**：成员输出像打字一样出现 |
| 离开后的通知 | **只在 Kern 里**：首页“需要你” + 侧栏角标 |
| 视觉 | **你定，做出来我看** |

## 确定的需求（v1，2026-09-26）

### A. 一次“我想开发一个新产品”的完整展示流程
1. **澄清卡**（对话内）
   - Kern 问 2–3 个关键问题：目标市场、预算、渠道、时间。
   - 每题都有可点选项，也可以自由填写。
   - 已在记忆里的信息直接显示“我记得：…”，并可修改。
2. **计划卡**（对话内摘要，工作区看全貌）
   - 内容：
     - 步骤、负责成员、依赖关系；
     - 为什么派这些人；
     - 预计额度消耗；
     - 会用到的记忆。
   - 操作：**确认开工 / 调整计划**（增删步骤、换成员、跳过）。
3. **进行中**
   - 对话内是一张实时进度卡：当前在做什么，以及 x/y 进度。
   - 右侧工作区的「过程」页签：
     - 每个成员一条时间线，输出**流式**出现；
     - 可展开到全透明：输入、方法/技能、工具调用、检索词、引用原文、模型、耗时、token/额度。
   - 干预：
     - 任务级：暂停 / 继续 / 取消；
     - 单步：重跑、跳过；
     - 随时补充信息：输入框里的补充会显示为“已带入后续步骤”。
4. **QA / 红队**
   - 质疑和修订要可见，标出“被打回 → 修订后通过”。
5. **结果**
   - 对话内是结论卡：推荐、置信度、关键理由、主要风险、需要你决定的事。
   - 右侧工作区的「产出」页签：
     - 机会报告（长文 + 引用）
     - 对比表（竞品 / BOM / 渠道）
     - 图表（市场规模 / 单位经济 / 趋势）
     - 验证计划、上市排期（清单）
     - 决策卡（推荐 / 反对理由 / 风险）
6. **带走**
   - 一键建成产品 / 项目 / 工作项：走现有 Proposal/受保护动作，有回执。
   - 导出 Markdown / PDF。
7. **元信息**：本次成本与额度、用到的记忆、升级原因。任何需要你的地方都写清“为什么是你”。

### B. 驱动方式
- 同一套组件由 **Mission 事件流** 驱动。
- 事件来源有两种：
  - 真实：supervisor / executor 产生的事件；
  - 演示：脚本化回放，界面上显著标注“演示数据”，不写入业务数据，也不占额度。
- 实时推送用 SSE；断线后退回轮询。

### C. 通知
- 只在 Kern 内：首页“需要你”，侧栏对话角标（完成 / 需要你）。

### D. 视觉
- 我来定：延续浅色 Kern 语言，工作区信息密度更高。做完截图给用户看。

### 不在本阶段
- Agent 产出质量、真实联网研究。
- 邮件 / 企业微信通知。
- 新产品之外场景的专门设计：只复用组件。

## 实现方案（草案）
| 层 | 做什么 | 保留 / 新增 |
|---|---|---|
| 事件模型 | `MissionEvent`：node.started/delta/tool/cite/finished、qa.revise、user.input、paused 等 | 新增 `KernMissionEvent` 表（append-only），替代 snapshot.log |
| 产出模型 | `MissionArtifact`（report / table / chart / checklist / decision），节点输出结构化 | 新增；executor 输出 JSON 契约扩展 |
| 控制 | pause / resume / cancel / skip / rerun / edit-plan / add-input API | 扩展 supervisor/service + plan 纯函数 |
| 流式 | `GET /api/missions/{id}/stream`（SSE，支持 `Last-Event-ID` 续传；断线退回轮询） | 新增 |
| 引用 | `node.cite` 带 `sourceCaptureId` / URL / fetchedAt，结论卡与导出沿用同一 id | 为 P1 citation lineage 预留 |
| 演示 | `demo` 回放器：按时间线写事件（同一张表，打 `demo=true`） | 新增，只在演示对话中；演示 mission 不用 `kern-mission/v1` schema 或在 billing 计数中排除，保证不占额度 |
| UI | 对话卡：澄清 / 计划 / 进度 / 结论；右侧工作区：过程 / 产出 / 信息 三个页签 | 新增组件，复用 kit |
| 带走 | 产出 → Proposal（CREATE_PRODUCT 等）；Markdown/PDF 导出 | 复用 proposals |

分 PR：
- ① 事件 + 控制 + SSE（后端）
- ② 工作区 UI + 对话卡
- ③ 演示回放 + 产出 + 带走
