## 当前结论

本轮修复本机命令自动放行、任务研究来源传递与报告状态、模型重试和切换的计数问题。本地包没有 Git 历史，本文报告本轮本地验证，不代表已发布、已合并或 GitHub CI 通过。

## 修复内容

### 本机权限

- 通用 shell 只自动放行完整匹配的有限读取命令，不再仅按前缀判断。
- 删除/创建分支、写文件参数、shell 展开、运行测试脚本、编译脚本均要求确认。
- 一次审批仍绑定完整动作指纹；服务端入队与执行领取使用同一策略。
- `npm test` 可以执行项目脚本，因此不再当作只读命令自动放行。

### 研究与来源

- 网页搜索摘要和抓取正文分别生成来源记录，保存来源标识、URL、获取时间、获取内容摘要、摘要 SHA-256 指纹和截断状态。
- 来源快照持久化到已有 `KernMissionEvent`，避免新增重复存储系统；此记录不等同于 `EvidenceSourceCapture` 的独立核验。
- 来源沿任务依赖传到后续节点、QA 和综合结论，保留原始记录标识；同一来源的继承副本不增加计数。
- 重跑、跳过、撤回和旧任务迟到回执不会继续作为当前有效来源；读取来源时分页，避免只读前 1000 条事件。
- 来源快照指纹不匹配或 URL 形状无效时不作为可引用记录。
- 报告有真实获取记录时显示“已联网，来源尚未独立核验”，来源仍标为“外部未验证”。检索摘要明确区别于正文抓取。
- 报告可以展开获取内容、打开原始来源；MD/PDF 导出保留来源、摘要、时间与指纹。
- 来源角标由稳定来源标识解析，无法解析的标识显示“来源未记录”，不凭空新增引用。
- 保存来源记录失败时停止该节点，避免把没有保存下来的来源当作已完成证据链。

### 模型额度

- 每次进入 provider 执行之前原子检查额度并创建独立 ModelRun，包括重试与切换模型。
- 配额拒绝发生在模型失败处理之外，不触发备用模型、不惩罚 provider 健康状态。
- 每次尝试分别记录成功/失败、耗时与可得 usage；provider 未提供的用量保持未知。
- TASK-010 已将旧顾问对话和专业分析接入网关，统一逻辑调用、预留与实际尝试、tokens 及预算；历史记录不反向补造传输事实。
- 模型预算在根任务内共享；未发送预留关闭后释放额度，实际失败尝试仍计入，金额未知保持未知。详见 `plan/kern-optimization-progress.md`。

## 本地启动

### 省去反复登录

运行 `npm run dev:local`，打开 `http://127.0.0.1:3100/login`，点击“本地测试一键进入”。
启动器幂等创建独立的“本地测试”账号和工作区，会话通过 HttpOnly Cookie 保留 30 天，刷新页面及重启服务不会清除；退出登录会撤销会话。
账号不设通用测试密码，已有用户和工作区不会被覆盖。此入口只有在显式启用的 development 模式、回环地址和同源请求下开放；production/test 模式拒绝签发。
开发服务仅监听 `127.0.0.1`，独立工作区需要自行配置真实模型等服务。

依赖与 `.env` 已存在。PostgreSQL 本地端口为 5432，默认网页端口 3100。不要复制历史 Linux 沙箱命令到此 Mac。

开发运行：

```sh
cd /Users/exasdwyh/Documents/VScode/Kern/pkg-full
npm run dev
```

本轮生产构建的运行方式：

```sh
cd /Users/exasdwyh/Documents/VScode/Kern/pkg-full
NEXT_DIST_DIR=.next-fixed NODE_ENV=production npm run start
```

入口：`http://127.0.0.1:3100/muse`，需要既有账号登录。不要覆盖已有账号口令。

持续执行需要另一个进程：

```sh
npm run worker:supervised
```

本轮启动网页用于检查入口；开发库的常驻 Worker 与 Mac Desktop Operator 未自动启动。启用它们之前，先确认现有待执行任务、模型配置和本机允许目录。
