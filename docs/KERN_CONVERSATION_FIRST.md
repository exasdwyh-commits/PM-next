# Kern · Conversation-first Agent Client

状态：**Active product direction**

## 1. 产品定位

Kern 的首要身份是一个干净的 Agent 对话客户端。

用户进入 Kern 后应该先看到对话，而不是：

- 今日待办仪表盘；
- 审批队列；
- 项目驾驶舱；
- 数字员工组织图；
- 一堆要求用户判断的卡片。

项目、工作项、产品、审批、证据、运行轨迹仍然存在，但它们属于 **管理工作台**。Kern 对话是日常操作入口。

```text
Kern Chat
  ↓
理解目标
  ↓
自己规划 / 路由 / 调顾问 / 使用工具
  ↓
执行能安全执行的工作
  ↓
回到同一条对话汇报结果

/manage
  = 项目 / 产品 / 看板 / 工作项 / 审计 / 批量管理
```

## 2. 用户交互原则

### 默认：少问，先做

用户已经明确表达目标时，不应把内部规划重新变成一串问题让用户回答。

例如：

- “把目标人群改成 25–45 岁女性”
- “建一个任务跟进供应商报价”
- “把这个产品建起来”
- “检查这个项目并修掉能直接修的 bug”

如果目标和对象明确，Kern 应推进并返回执行结果。

### 只在真正需要人时打断

以下类型才需要二次确认或最小澄清：

- 支付 / 下单 / 财务承诺；
- 正式发布 / 上线 / 对外发送；
- 删除或不可逆覆盖；
- 高权限或敏感权限变更；
- G1 / G2 / G3 等正式业务 Gate；
- 法律、合同或外部承诺；
- 多个目标对象无法可靠区分；
- 缺失的信息会改变执行结果，且无法从上下文安全推断。

“系统内部可逆写入”不是默认的人类 Gate。

## 3. 对话与 Work

Work 不是另一个首页，也不是要求用户管理 Agent。

它是对话里的一种运行状态：

```text
用户：把这个仓库检查一下并修好

Kern：
我来处理。
  ↓
内部：plan → agents → tools → validation
  ↓
Kern：
完成。修了 3 处，测试通过。这里是变更摘要。
```

用户想看过程时，再展开：

- 运行轨迹；
- Evidence；
- Visual Intelligence；
- Agent / Tool 细节。

默认不展开。

## 4. 管理工作台

`/manage` 继续承载：

- 产品管理；
- 项目看板；
- 工作项；
- 风险与证据；
- 批量审批；
- Workforce；
- 审计 / Trace；
- Model Control。

这是“管理系统”，不是 Kern 本人。

## 5. Visual Intelligence

Visual Intelligence 是对话工具，不是默认 UI。

仅在以下情况主动展示：

- 用户明确要求“画一下 / 可视化 / 关系图 / 结构图 / 拆解”；
- 未来某个结果确实必须通过图才能表达，且 UI 允许用户折叠。

普通复杂咨询即使调用了 Council，也不自动塞一张顾问团图。

## 6. Autonomy

当前确定性对话写入中：

- UPDATE_FIELD
- CREATE_WORK_ITEM
- CREATE_PRODUCT

当它们来自对应的明确用户指令时，Kern 将用户这条指令视为一次授权，复用现有 Proposal 的权限、版本、CAS、幂等与审计链后直接应用，不再要求用户第二次点“确认”。

Proposal 在这里仍然是**内部事务/审计协议**，不再等于必须出现给用户的审批卡。

受保护动作仍走原有 Governance / Approval / Gate。
