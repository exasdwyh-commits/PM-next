## 3. 这条片子守的规矩

- **设计语言**：`src/app/theme/kern-design.css` 的令牌原样搬进片源（画布 `#EEF2F8`、表面白、强调 `#2563EB`、正文 `#0F1B33`），没有新造颜色；卡片圆角 20px、阴影用现有三档；无渐变背景（唯一一处是卡片后 5.5% 的极淡品牌光晕，用于收视线）；无 emoji 图标，文件类型用文字块（XLSX / DOCX / PDF）。
- **动效规范（§5）**：只动 `transform` / `opacity` / 颜色；单次 ≤600ms（尺寸变形 560ms、内容切换 220ms、按下 140ms）；全片唯一的循环是幕 1 的输入光标，它只表示「正在输入」，随该幕结束离开画面。
- **不用硬切**：七幕共用一个 `[data-morph]` 物体（输入条 → 宽卡片 → 收束句），幕与幕之间只有宽度、内边距与层的淡入淡出，没有切换镜头；同一时刻只有一个东西在变形。
- **状态真实**：故事轨五站、日志只列真实工具调用语义（含失败重试）、推断 / 被推翻 / 未知 / 需要你决定逐条可见——与产品里 KX-23 / KX-24 的实际行为一一对应，不是画出来的好看假界面。
- **示例数据的边界**：片中是演示任务（燕麦脆竞品价格），数字为演示值；不外冒真实客户数据，也不宣称产品能力之外的东西（没有「自动签字」「全自动上线」这类话）。

## 4. 复现

```bash
# 1. 录屏：片源在 Edge/Chromium 里按真实时间轴跑一遍（1920×1080），落 webm
cd PM-next && node scripts/_kx41-render.mjs        # 片源路径见脚本内 DIR

# 2. 合成：webm + 7 段旁白 → 成片（旁白 1.2× 语速，响度归一 -16 LUFS）
cd ../outputs/kern-film && mv -f page@*.webm film-video.webm
ffmpeg -y -i film-video.webm -i vo/01.mp3 … -i vo/07.mp3 \
  -filter_complex "[1:a]atempo=1.2,adelay=800|800[a1]; … [a7][a2]…amix=inputs=7:normalize=0,loudnorm=I=-16:TP=-1.5:LRA=11[out]" \
  -map 0:v -map "[out]" -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -r 24 -movflags +faststart \
  -c:a aac -b:a 160k -t 63 kern-film-1080p.mp4
```

两条经验，避免再踩：

- **时间轴按 ffprobe 实测时长排**。TTS 的 mp3 是 112kbps / 48kHz，按文件体积估时长会差三倍（7 段实测合计 65.8s，估算只有 19s）；`ffprobe -show_entries format=duration` 才是准的。
- **带 `-t` 截断**。录屏 webm 的实际时长会略长于脚本时间轴（浏览器起播、字体加载），用 `-t 63` 锁住片长，否则末尾会拖一段静止画面。

## 6. 没做的、可选的

- **背景音乐**：未加（办公场景默认静音，且需要版权明确的音源）。需要的话给个 BGM 文件即可混入，混音口子已经留好（`amix` 前再加一路）。
- **字幕轨**：旁白全文见本文件 §2，可直接生成 `.srt`；片源里也已按幕标注（右下角「01 · 一句话」…），静音播也能看懂。
- **竖版 9:16 / 英文版**：片源是 16:9 固定画布，改这两项需要重排分镜（改 `body` 尺寸与卡片宽度即可，动效不受影响）。
