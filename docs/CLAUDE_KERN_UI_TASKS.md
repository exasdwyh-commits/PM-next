## 最高优先级补充：对话回复的 HTML 可视化体验

2026-10-09 用户纠正：最主要需求是 Kern 的对话回答能够像 Claude 网页端那样，有漂亮的 HTML 排版、可视化与交互。先交付回复体验，再继续首页装饰。此要求覆盖后面的旧排序。

参考官方 Artifacts 模式：内容可以成为独立网页、图表、仪表盘和交互工具，并在会话旁展开。这里借鉴交互与呈现方式，不声称 Claude 所有普通回答均为任意 HTML。
官方参考：https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them

### TASK 0 · Kern 富回复与 HTML Artifact（先做）

**用户看到的效果**

- 普通回答直接在对话内呈现精心排版的内容：摘要、强调、分栏、比较表、信息卡、来源；不要求用户阅读 HTML 代码或点击下载才看见。
- 当分析适合可视化时，自动提供可直接预览的 HTML 报告/交互图表。消息中展示预览与“展开”，桌面在会话旁打开可调整宽度的阅读区，手机全屏打开且能返回原消息。
- 支持“把这份分析做成可视化”“改为对比视图”“突出风险”等自然语言迭代，同一成果有稳定标识和版本，历史版本可回看。
- 支持复制正文、下载独立 HTML；导出包含必要样式和数据，离线打开可用。简单一句话回复保持轻量，不强制仪表盘模板。

**实现建议与边界**

- 先追踪真实发送接口 → 模型输出 → 消息保存 → 历史恢复 → 渲染链路。现有 `ResponseEnvelope` / `ResponseView` 已有结构化表格和图表，不能把当前情况简化为“只有 Markdown”。在这个基础上扩展富内容和 artifact 的消息载荷。
- 建议采用两层：常规富回复用受控 React 组件渲染；需要自由构图与交互的完整 HTML 用隔离的 iframe 预览。让 Claude 充分设计 HTML 的布局、SVG、图表、折叠、切换与轻量互动。
- 明确定义 artifact 的 id、版本、类型、标题、内容、生成状态与关联消息，并接入现有账号/会话归属和历史持久化。协议或存储确有缺口时允许最小后端改动；这一条是后文“本轮前端为主”的明确例外。
- 流式生成先展示文字与生成状态；HTML 完整后原子替换预览，避免将未闭合标记逐 token 执行。生成失败仍能阅读已有文本并重试。
- HTML 不直接注入主应用 DOM；需要脚本的交互在 sandbox iframe 内运行，不授予 same-origin，不读取应用 cookie/token，不任意访问网络或调用业务 API。父子消息校验来源窗口、artifact 标识和消息结构。真实采纳/启动任务使用宿主应用已有处理器。
- 不凭漂亮布局增加虚假数字、来源、百分比或进度；假设/UNKNOWN/来源在 HTML 中也要清楚。没有足够数值时采用比较卡、时间线或因果图。

**交付与验收**

1. 正式 `/muse` 发出真实请求，回复生成可视化，能在消息内预览、展开、关闭；不能只做静态 demo。
2. 用产品方案比较、成本分析、任务计划三类回答展示不同构图；模型不能调用时明确说明哪些验证用了固定样本。
3. 点击图表、切换标签、展开细节有效；图表数值与回复数据一致，来源仍可查看。
4. 刷新与重新打开历史会话后内容、版本、来源都在；继续对话修改同一成果能产生新版本。
5. 390px 手机、桌面与深色可读；导出 HTML 离线打开有效；恶意 HTML 无法读主页面或触发真实业务动作。
6. 展示真实回复截图/操作录像，交付实现文件与可运行入口，再推进其他美化。

## 后续：整页视觉基准

### TASK 1 · 正式首页的 Advanced Bento

- 开发前展示一张现有 `/muse` 截图和一张原型参考截图，指出要保留的构图、材质和密度。
- 做一版完整正式首页：mesh 欢迎区、工作视角、玻璃 KPI、环形/条形图、待处理事项和快捷任务。
- 让玻璃层次、渐变标题、彩色阴影、留白和字体层级接近原型；内容字号保证日常阅读，不照搬原型过小的 10–11px 正文。
- 已加载事项、过去一天完成量取真实 `ChatBrief.attention`。未知显示待更新；空状态仍是完整设计。
- 有产品上下文时才用真实产品名称/分类；通用对话不默认成“多酚软糖/保健食品”。
- 每个可点卡片有真实去向；“待处理/推进中”卡片跳到相应事项，不增加空回调按钮。

**验收：**实际 `/muse` 首屏与原版明显不同；图表与数值一致；点击 KPI 能到达对应事项；提供桌面/手机截图。

### TASK 2 · 对话、输入区和工具统一视觉

- 美化消息层级、会话左栏、顶部工具、输入框、快捷任务及浮层，统一为同一套 advanced 视觉。
- 正文阅读面保持稳定，玻璃与 mesh 用于表面和环境；hover、磁性/轻量 3D 用在可操作卡片和按钮。
- 长草稿、读取历史、发送中、失败重试都有明确状态，布局不抖动，最后一条回复不会被输入框遮住。
- 已有工具、模型/能力选择、草稿刷新恢复、对话归档与恢复保持可用。
- 深色/浅色/跟随系统选项可恢复，作用域限 Kern；项目/管理页面保持独立。

**验收：**真实输入 → 发送接口反馈；长草稿刷新恢复；工具面板可打开关闭且键盘焦点返回；手机控件可触摸。

## P1：把执行动效与结果交付做好

### TASK 3 · 真实状态驱动的流程动效

- 保留 n8n 式目标 → 节点 → 连接 → 并行分支，升级玻璃节点、连线、状态标识和选中详情的视觉。
- 运行/等待/阻塞/暂停/成功/失败有各自可读状态。动效由已有 `MissionStatusView`、事件与连接状态驱动。
- 节点只在真实执行时表现活跃；暂停或结束后动效停下来；断线保留最近状态并说明连接情况。
- 新节点入场、工具活动、完成与详情展开做有节奏的过渡，不能定时制造进度或每次刷新重播整个流程。
- 桌面支持并行 DAG；手机默认步骤列表且保留图形入口；缩放、拖动、定位、详情焦点继续有效。

**验收：**任务开始 → 进展 → 暂停/API200 → 刷新后仍暂停 → 继续；断线重试不启动第二次任务；减少动效时关闭视觉过渡。

### TASK 4 · 结果阅读和下一步

- 用高级卡片呈现一句话结论、关键数据、表格、图表、风险、来源、决策与下一步，保持完整信息入口。
- 自定义图表可以充分美化，但数值、单位、标签、负数/零值都来自实际 envelope；无数据时不画样本数。
- 摘要/完整和章节导航一致；点击来源角标能到达当前这份报告的来源，不能串到另一条回答。
- 未知、推断、风险与反对意见保持可见；事实标签不自动变成 A 级可信证据。
- 决策选择、任务继续、复制和下载接已有处理器；演示选择明确标注演示。

**验收：**来源跳转、摘要/完整、下一步点击 → 实际保存 → 刷新保持 → 后端反馈；不只看按钮颜色变化。
