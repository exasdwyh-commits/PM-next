# Kern 回复格式规范（kern-reply-format/v1）

Kern 的每一条回复都经过三层：

| 层 | 位置 | 职责 |
|---|---|---|
| 规范 | `src/modules/assistant-runtime/reply-format.ts` → `KERN_REPLY_FORMAT_PROMPT` | 注入所有 ASSISTANT_* 人格与任务综合结论，告诉模型怎么写 |
| Harness | 同文件 `normalizeReply()` / `lintReply()` | 入库前修复常见错误；修不了的记入 `toolCall.resultJson.replyFormat` |
| 渲染 | `src/app/muse/components/prose.tsx` + `muse.css`「Kern 回复排版」 | 只渲染这套子集，其他一律按纯文本，无 HTML 注入 |

## 写法（给模型的规则，摘要）

1. **先给答案**：第一段就是结论，不寒暄、不复述问题。
2. **按长度选结构**：简单 1–3 句；中等 段落 + 至多一个列表；长回复 摘要 + `##` 分节（≤5）。
3. 标题只用 `##` / `###`；列表 `- ` / `1. `，最多两层；每段最多一处 **加粗**。
4. 对比用表格（有表头、≤6 列、数字列 `---:`）；代码块标语言。
5. 提示框每条回复最多 2 个：`[!DECISION]` 需要你决定 · `[!WARNING]` 注意 · `[!TIP]` 建议 · `[!NOTE]` 说明 · `[!UNKNOWN]` 待验证。
6. 推断标 `（推断）`，缺数据标 `（待验证）`，渲染为行内标签。
7. 结尾最多一句下一步或一个问题。禁止原始 HTML、Mermaid、表情符号。

## Harness 自动修复

去掉“好的/当然…”开头 · `#`→`##`、`#####+`→`###` · 未闭合代码块补齐 · 原始 HTML 去标签（`<br>` 变换行）· `* + •` 列表统一为 `-` · 提示框别名（`[!注意]`→`[!WARNING]` 等）· 表格列数不齐补齐/合并 · 连续空行压缩。代码块内部不动。

Lint 只报告：`headings-on-short`、`too-many-sections`、`too-many-callouts`、`emoji`、`no-lead`。

## 排版

- 一个节奏单位 `--rh`，所有块间距由它推导，段落/列表/表格/代码/提示框呼吸一致。
- 标题靠字重和前置留白区分，不靠大字号；有序列表用圆形序号，无序用强调色圆点，二级空心。
- 表格：数字列自动识别，右对齐等宽；窄屏横向滚动，不撑破页面。
- 代码块：深色面板，语言标签 + 复制按钮。
- 提示框：颜色即语义；「需要你决定」最醒目，「待验证」虚线最轻。
- 亮/暗主题、手机宽度（≤640px）、打印均已适配。工作区步骤产出与决策卡使用紧凑变体。
