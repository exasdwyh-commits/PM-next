# HERMES 模块体验优化方案

日期：2026-09-14。基于当前源码检查；未做浏览器实测，不宣称运行验收通过。本轮仅规划，不修改业务实现。

## 结论

沿用五个主模块，不再扩展导航。以产品为业务中心，以顾问为跨模块助手，把每页组织成“看结论 → 做当前动作 → 按需查依据”。本次重点是收敛现有实现，不另起架构。

## 1. 已确认的问题

| 问题 | 源码依据 | 影响 |
| --- | --- | --- |
| 五个主入口之外常驻六个“更多”入口 | `src/components/app-shell.tsx` 的 MORE_ITEMS | 项目作战室/产品开发、顾问议事厅/AI 顾问、数据看板/工作总览并存，用户需自行判断入口 |
| 产品总览六组面板平铺，下一步重复出现 | `src/app/products/[id]/product-overview-client.tsx` | 缺少明确主次，摘要与操作脱节 |
| 成本和验证页签显示 NOT WIRED 及接入模型说明 | 同上 | 业务工作中出现开发交接文案，且流程不能在产品页完成 |
| 方案页主要是历史记录和原始 JSON；修改入口在分析页 | 同上及 `revision-panel.tsx` | 查看当前方案、修改方案和比较版本被拆开 |
| 顾问页常驻长能力说明、提议记录与多组快捷词 | `src/app/advisor/advisor-client.tsx` | 对话被管理信息挤压；缺少稳定的工作焦点 |
| 顾问尚未实际调用模型，当前是白名单查询/规则路由 | `src/modules/advisor/service.ts`、顾问页能力说明 | 功能接线存在，不等于专业自然语言顾问已完成 |
| URL 产品参数与默认选取的最近会话分别处理 | `src/app/advisor/page.tsx` | 存在产品上下文与所显示历史会话不一致风险，需优先以测试核实并约束 |
| 知识页面混合检索、来源、事实维护、成果归档 | `src/app/knowledge/knowledge-client.tsx` | 日常查资料和管理员维护的工作模式混杂 |

这些结论针对已读源码；视觉拥挤程度、滚动距离、响应式表现需下一步用浏览器验证。

## 2. 模块职责与入口收敛

侧栏固定：工作总览 / 产品开发 / AI 顾问 / 市场机会 / 公司知识。底部仅设置与用户信息。

| 现有入口 | 新位置与迁移方式 |
| --- | --- |
| 数据看板 | 总览的深入统计，不再独立主入口 |
| 项目作战室 | 产品详情中的执行任务；暂未绑定产品的项目放产品开发下“探索项目”，避免丢失 |
| 顾问议事厅 | 产品详情的协作记录，保留反馈处置能力 |
| 决策追溯 | 产品详情“决策记录”；全组织审计在设置 |
| 组织与权限 | 设置子页 |

先完成内容映射和导航承接，再移除重复入口。旧 URL 保留并重定向到正确对象/页签；无法准确映射时显示选择页，不一律跳首页。不删除底层记录和接口。

## 3. 逐模块优化

### 工作总览：只回答今天如何推进

顶部紧凑摘要：待我处理、阻塞产品、近期上市。主体左侧约 2/3 为“今日行动队列”，右侧为“需要关注”。

- 行动队列整合任务、待裁决、待确认提议，按紧急程度和日期排序；展示类型、所属产品、责任人、截止日与直接动作。
- 同一阻塞只生成一条主要行动，其他卡片引用，不重复计数。以业务对象 ID 去重，不以标题去重。
- 产品推进显示产品、当前阶段、当前卡点、下一里程碑；点击进入产品详情。
- 机会只展示少量相关摘要，趋势统计放二级查看。
- 首页不摆入库表单、长报告或审计流水。空队列表示暂无待处理；缺数据或查询失败单独说明。

### 产品开发：列表负责找产品，详情负责推进产品

列表默认表格，可切看板。筛选先保留阶段、负责人、是否阻塞。列为名称、阶段、负责人、下一步、目标上市日；评分作为可选列，低覆盖暂评不能与完整分数混排。

产品详情固定头部只保留产品名、版本、阶段、负责人、目标上市日和一个主动作；次操作收进菜单，“问顾问”作为稳定辅助入口。

详情沿用现有六页签，避免再次改动整体导航：

| 页签 | 默认内容 | 收起的内容 |
| --- | --- | --- |
| 总览 | 一句话结论、当前卡点、下一步按钮、产品定义摘要、近期里程碑 | 完整定义、评分依据、审计历史 |
| 分析与评分 | 结论 → 最重要的三项问题 → 可采取的优化建议 | 逐维度依据、假设、权重、引用详情 |
| 方案与版本 | 当前完整方案，可提出修改；左右版本差异 | 历史版本列表、拒绝项记录；JSON 仅管理员诊断入口 |
| 成本与供应 | 当前方案的成本输入、计算结果、报价来源 | 详细计价参数和情景模拟 |
| 验证与风险 | 待验证事项、已有结果、阻塞项 | 原始证据和核验记录 |
| 上市计划 | 时间线/任务清单、负责人、日期和阻塞 | 放行规则解释、历史放行记录 |

“建议下一步”必须能执行：如“补充渠道报价”打开对应表单，“调整目标人群”打开方案修改，“确认上市计划”进入对应页签。不能只显示“按建议推进”。

分析页可启动修改，但复用方案页同一个修改流程。每次采纳显示旧值、新值、理由和影响，生成新版本后返回当前产品，不跳到另一套项目界面。页签写入 URL，支持刷新、返回和分享定位。

成本与验证当前没有接通：优先将已有项目证据、缺口和成本引擎通过产品关联接入。存在多个项目时显示明确执行范围，不随便取第一个。接通前展示“尚未录入报价/验证记录”和真实可用的关联项目入口；缺功能时明确“暂不可用”，不能把未实现伪装成空数据。模型、表结构等开发说明移到交付文档。

上市计划按阶段展示动作：未建计划→建立；进行中→处理阻塞；满足条件→申请放行；已批准→记录实际上市。不要把建立、放行、实际上市三个阶段的表单同时展开。

### AI 顾问：以对话为主体，成果按需展开

左栏为可折叠会话列表，中间为对话，右侧上下文/成果抽屉默认收起。输入框保持可达；新会话最多三条相关示例，已有会话不常驻整排通用提示词。

顶部范围条显示“全公司”或产品名称+版本。会话自身保存产品绑定，打开旧会话必须恢复它自己的上下文；从产品进入时选择该产品会话或创建新会话，不把另一产品会话仅用 URL 改标签。范围切换明确新建/切换会话，发送前服务端核实权限与绑定。

提议卡附着在生成它的那条消息下面；确认后变成一行执行结果，可展开看变更和回执。其他历史提议放成果抽屉，避免占住对话顶部。

引用可点击查看原文及日期。真实模型未接通前，顶部短状态明确“结构化查询模式”；详情在能力说明里。完成真实模型连接、多轮上下文和失败恢复之后，才启用专业顾问的能力表述。免费/Luna 端点按既有要求验证，不自动付费升级。

重点行为检查：首次发送后 URL 持有会话 ID，后续消息写回同一会话；切换会话不带入上一会话草案；失败消息可重试且不重复写入；中文输入法组合输入时 Enter 不误发送。

### 市场机会：从信息列表变成可判断的机会

原始信号归入“资料”；用户默认看机会摘要：发现了什么、为什么适合公司、依据、最大未知项、建议验证动作。

使用工作状态“待判断/待验证/已转产品/暂不跟进”，独立于真实性和核验状态；采集成功不代表验证通过。重要度不等于商机价值。

先提供来源查看、关联已有产品、转为产品想法三种动作。转入产品保留来源并幂等，不能重复生成多个同名产品。录入或采集配置放按钮后的抽屉/设置，不常驻主页面。

### 公司知识：日常使用和维护分离

默认“查资料”，提供自然语言搜索和按公司概况、渠道政策、产品资料、决策复盘分类浏览。结果展示可读标题、摘要、来源、日期和确认状态；“切片”改为“引用段落”。

“公司概况”展示经确认的事实，有来源、有效期和编辑入口。技术 key 不作为普通用户必填项；以中文字段选择及内容录入替代。

数据源连接、目录、同步日志移入“管理知识源”，仅相应权限可见。已验收成果纳入文档分类，保留项目关联，不与搜索结果竞争整页空间。引用文档可发起带该资料的顾问对话。

## 4. 全站交互标准

- 每屏一个主动作；同一个动作全站同名，同一状态由共享映射输出中文。
- 标题和卡片不要处处重复英文 eyebrow；技术术语仅在有助决策时展示。
- 三层信息：默认结论；展开依据；诊断/审计放详情。不把规则解释写成长常驻警告。
- 无数据、无权限、未实现、运行失败四种状态分开，有各自准确动作。
- 一个产品上下文贯穿分析、顾问、任务和上市；返回能恢复筛选、页签和滚动位置。
- 保持当前视觉方向，统一内容宽度、标题层级、组件密度；不在本轮另起新主题。
- 任务、提议、验证、上市分别保留真实状态；面向用户映射一致，但不为了文案统一强行合并数据枚举。

## 5. 执行优先级与分工

| 优先级 | 工作包 | 依赖及验收 |
| --- | --- | --- |
| P0-1 | 收敛导航与旧入口映射 | 先列所有旧能力落点；无数据或入口丢失 |
| P0-2 | 顾问会话/产品上下文一致性 | 验证产品 A/B 切换、首次发送及连续发送；显示范围与服务端范围一致 |
| P0-3 | 产品总览及方案页重排 | 能从总览直接开始当前任务，并在方案页完成修改和版本对比 |
| P0-4 | 真实模型接入及成本/验证接通 | 与界面整理并行，至少一个真实端点；不得用占位卡充当完成 |
| P1-1 | 首页行动队列、顾问对话布局 | 依赖共享动作和路由契约；去重且动作直达 |
| P1-2 | 知识使用/维护分离、上市渐进操作 | 功能保留，默认页面负担下降 |
| P2 | 机会归纳与转产品、样式细化 | 主线可用后再做 |

可分为三个实施责任：A 导航/总览/公共组件，B 产品六页签及业务聚合，C 顾问/知识。模型接入由 C 负责，B 接消费契约；机会收尾再安排。共享 CSS、路由映射、数据库 schema 各有唯一所有者，禁止三个 agent 各改一套。当前未提交变更多，实施前登记所有权并保留他人修改。

这次交付按用户旅程验收，不按“修改了几个模块”验收：
1. 总览发现卡住的产品 → 打开详情 → 看依据 → 采纳修改 → 看新版本。
2. 产品进入顾问 → 引用公司资料 → 生成一项提议 → 确认 → 查看同一产品中的结果。
3. 产品查看已有验证资料 → 关闭有依据的缺口 → 推进上市计划。
4. 市场资料 → 机会判断 → 转入产品 → 来源仍可追踪。

正常、空数据、失败和无权限均做浏览器检查；1280/1440 宽度及窄屏抽查。构建和核心权限/版本/会话集成检查通过后，再做实际业务演示。不要仅凭颜色统一或路由可访问判定完成。
