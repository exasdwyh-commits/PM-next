# 基础体验标准化 · 2026-10-10

## 本轮确认的方向

- GitHub 是代码与验收结果的统一来源；改动通过独立分支 / PR 同步，测试优先在 GitHub Actions 执行。
- 每日新闻暂缓扩展，不引入抓取、定时新闻任务、视频、配音或转场依赖。
- 优先标准化基础体验，再扩展周边功能。
- 项目展示优先产品方案、研发流程、路线图、竞品对比和证据关系，而非先做代码架构探索。

## 这一批基础改动

1. 对话入口先展示欢迎与目标入口，再渐进展开项目进度；建议仅追加可审查草稿，不自动发送。
2. 次要工具与复制对话收拢到更多入口，保留原有回调、键盘关闭与焦点恢复。
3. 模型、本机连接、记忆来源与空状态按实际状态表达。
4. 输入区按真实高度给内容预留空间，兼顾手机和减少动态效果设置。
5. 首次使用同时检查产品与独立项目，减少重复全零面板；不隐藏真实告警、阻塞与待处理记录。
6. 项目简报只反映读取到的记录，明确读取口径；零分母、读取失败和不存在的项目不伪装成真实数据。
7. 每日简报消费者兼容空项目、空建议；通知派发、认证、审批与 Agent 执行链不在本批改动范围内。

这里的“项目简报”不是每日新闻功能。没有项目时只显示简短引导，不占据完整仪表盘。

## 验收标准

- GitHub PR 展示可审查的 diff；不直接覆盖 main。
- 类型、现有前端契约、首页契约与专项浏览器检查均应有云端结果。
- 浏览器证据覆盖桌面 / 390px 手机、草稿保留、更多工具、错误重试和输入区增长。
- 测试使用隔离数据库 / 标注的合成夹具，不访问生产数据、不上传密钥。
- 合成界面检查不能代替真实模型、登录、审批和数据库端到端验收。
- 没有成功的 Actions 结果就不能宣称已完成测试；已有 main 失败与新增回归分别记录。

## 项目成果展示的后续标准化

沿用已有成果协议与隔离边界，按内容选择模板，不为所有成果强套架构图：

- 项目方案：目标、约束、关键假设、依据、下一步。
- 流程与路线图：阶段、依赖、负责人、确认状态与未知项。
- 竞品对比：同一指标口径、来源与采集时间。
- 证据关系：区分已确认、推断与未知；可追溯到真实资料。
- 展示：紧凑摘要、按需展开、手机列表降级、离线可读、安全导出。

Diagram Design / Archify 是设计与生成工作流参考，不因安装或生成 JSON 就宣称已完成集成。外部代码与素材复用前核对许可证。
