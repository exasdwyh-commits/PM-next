## 1. 关键架构决定记录 (ADR)

### ADR-01: 采用独立真实 PostgreSQL 实例 (Port 5433)，彻底弃用 SQLite/PGlite
- **背景**：本机 5432 端口已被 Python 进程占用；旧版原型使用 SQLite。
- **决定**：使用本机 PostgreSQL 17 工具链，在端口 5433 建立独立数据目录 `.pgdata_hermes_next`、专用库 `hermes_next_dev` 与账号 `hermes_app`。
- **理由**：同一项目有人类提交和后台任务并发写入，PostgreSQL 提供真正的行锁、ACID 多表事务原子性与外键约束；避免未来 SQLite 到 PG 的二次迁移成本。

### ADR-02: 结构化元数据计算 scopeHash，而非富文本整页 Hash
- **背景**：旧版尝试对整页文本或宽泛字段取 Hash，排版调整或新增常规评论时易导致批准意外失效。
- **决定**：严格提取排序后的结构化数组（`artifactVersions`, `evidenceVersions`）、预算金额、预算授权范围和验证计划，拼接规范 JSON 计算 SHA-256。
- **效果**：评论与非业务排版改动不会破坏批准有效性；关键技术指标或预算变化能精准识别并使旧批准进入待复核。

### ADR-03: 防自批与强会话隔离
- **背景**：避免项目负责人（PM）在缺少监督情况下自行审批高额研发预算。
- **决定**：系统强行校验 `session.userId !== project.ownerId`。若负责人尝试调用决策接口，立即返回 403 Forbidden；组织管理员也不具备自动业务批准权。

## 2. 已知问题与后续包处理建议

1. **当前阶段仅开放至 SAMPLING**：
   - B01 按规格仅开放至研发打样阶段；生产准备与放行（PRODUCTION_PREP $\to$ PRODUCTION）在 B01 保持不可执行提示，需在 P2 生产放行包中接入包装、规则合规审核及供应商报价后解锁。

   - B01 目前仅支持人工录入 (`MANUAL`) 与测试替身 (`TEST_STUB`)，并在数据中明确如实标记。真实大模型编排、上下文持久化将在后续包专门接入。

   - 目前证据录入支持来源哈希与内容校验；蝉妈妈等外部 API 已具备契约定义与 skill 工具，将在 P3 阶段整合为自动化定时同步流。
