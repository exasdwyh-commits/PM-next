# Kern 动效原则（从「教学动画导演提示词」提炼）

来源：用户提供的一份面向 75–98 秒教学动画的导演提示词（七幕结构、分镜、转场图、声音计划等）。
这份提示词是为**做一支动画片**写的；Kern 是**工作软件**。本文只提炼其中可迁移到产品界面的原则，
并逐条说明「采用 / 改写 / 不采用」及原因。所有动效仍受 `docs/mcp-kern-experience-roadmap.md` §4 工艺守则与 §5 动效规范约束，
由 `tests/motion-contract.test.ts`、`tests/motion-primitives.test.ts` 锁定。

## 1. 采用的原则

| # | 提示词原文要点 | 在 Kern 里的落法 | 落地位置 |
|---|---|---|---|
| P1 | 把主题压缩成**一个核心因果**，用一条视觉故事讲，而不是罗列事实 | 一次任务只讲一件事：「你交代的话 → Kern 交回的成果」。任务卡顶部用一条故事轨（理解需求 → 简报 → 计划 → 执行 → 交付）代替零散的状态字段 | `StoryRail` + `src/app/muse/mission-story.ts` |
| P2 | 固定的幕次，**每一幕都要带来新理解** | 故事轨站点固定 5 站；只有真实字段变化时才前进一站（有契约 → 简报；有节点 → 计划；节点开始 → 执行；outcome 完成 → 交付），不会为了「显得在动」而前进 | `storyPhase()`，`tests/mission-story.test.ts` |
| P3 | **不用硬切**：线变成路径、粒子重组成物体；每个转场都要**承载意义** | 当前站的圆点「长成」带文字的 pill，已走过的连线变成品牌色——前进这个动作本身就是信息。动态岛的文字换新时，新文字从下方升起，旧的让位 | `.kx-rail`、`Notch` |
| P4 | 每个镜头**只有一个主要视觉想法**；关键变形要**留出呼吸** | 同一时刻只有一个物体在变形（§5 规则 1：尺寸动画只许 `[data-morph]`，同一时刻一个）；变形用 `--m-d-morph` 560ms，小元素 220ms | `Notch[data-morph]`、`Drawer` |
| P5 | **一致的角色**：同一个吉祥物做讲述者，轮廓、比例始终不变 | Kern 的 K 标是唯一的「讲述者」：动态岛、页脚、侧栏都用同一枚 K 标，大小比例固定，不另造形象 | `Notch`、`PublicFooter` |
| P6 | 先说**具体的话**，再上技术名词；**旁白不要和屏幕文字重复** | 动态岛只说「此刻在做什么」（currentActivity），故事轨只显示当前站的文字，其余站只给读屏；日志只放工具调用，不复述动态岛 | `buildStory()` |
| P7 | 要有**字幕** | 对应到无障碍：动态岛 `role="status" aria-live="polite"`，日志 `role="log"`，故事轨 `aria-label` 读出「第 N / 5 步」。降动画时文字完整，信息不丢 | `@/components/kx` |
| P8 | 严谨：**保持准确**，不为好看牺牲正确 | 对应 §5 规则 5「状态必须真实」：假设 / 证伪 / 收回事件逐条可见（诚实节拍），被推翻就明说「被推翻」，不淡化 | `Beats` |

## 2. 改写后采用

| 原文 | 改写 | 原因 |
|---|---|---|
| 「stop-motion boil」：形状每几帧抖动 1–2px | **只保留一个呼吸点**：动态岛里的小圆点在「进行中」时呼吸（`kx-live`，已登记循环白名单），状态结束立即停 | §5 规则 2：循环动画只用于表示「进行中」。常驻抖动在工作软件里是噪音 |
| 「声音计划」：音乐、环境声、触感音效 | 不加声音；「同步的触感」改写为**按下反馈**（`--m-ease-press`，140ms） | 办公场景默认静音；系统通知已由 KX-64 负责 |
| 「每个场景写 入场 / 主动作 / 次级反应 / 退场」 | 组件动效按这四拍设计：抽屉 入场（遮罩淡入 + 面板滑入）/ 主动作（内容可操作）/ 次级反应（焦点移到关闭按钮）/ 退场（焦点回到触发者） | 四拍结构对交互同样有用，且能落到可测的无障碍行为上 |
| 「转场图」 | 本文 §4 的状态转场表：每一次变化由哪个真实事件触发、哪个物体承接 | 让「转场承载意义」可以被测试断言 |

## 3. 不采用

- **撕纸、水粉、蜡笔、铅笔质感，珊瑚 / 芥末 / 青 / 奶油 / 炭灰配色，终端窗里的小舞台**：§4 守则 1 要求沿用 Muse「安静画布 + 单一强调渐变 + 大圆角」，不自造令牌外的颜色；§4 守则 3 禁止用手绘插画冒充图片。
- **像素吉祥物**：不另造形象，K 标即讲述者（见 P5）。
- **75–98 秒、1920×1080、24fps 成片**：这是 KX-41「可选：代码渲染的产品短片」的范围，届时可按本文 §1 的原则 + 原提示词的七幕结构来写分镜。

## 4. 状态转场表（KX-23）

| 真实信号 | 故事轨 | 动态岛 | 承接物体 |
|---|---|---|---|
| 状态快照到达、无契约无节点 | 理解需求 | currentActivity | 第 1 站圆点长成带文字的 pill |
| `contract` 出现 | 简报 | 同上 | 第 1→2 站连线变色，第 2 站长成带文字的 pill |
| `nodes` 出现、均未开始 | 计划 | 同上 | 同上 |
| 任一节点 ACTIVE / SUCCEEDED / BLOCKED / FAILED / SKIPPED | 执行 | 同上；日志开始出现工具调用 | 同上；日志新行升起 |
| `pendingAsks` 非空 | 不变，带文字的 pill转警示色 | 「有个问题等你回答，其余步骤照常进行」 | 动态岛呼吸点停止 |
| `paused` | 不变，警示色 | 「已暂停」 | 同上 |
| `node.hypothesis` / `node.refuted` / `node.retracted` | 不变 | 不变 | 诚实节拍新行升起 |
| outcome = COMPLETED | 交付 | 「已完成，可以带走结果」 | 最后一站长成带文字的 pill，日志收起 |
| outcome = NEEDS_USER | 不变，警示色 | 「停下了，需要你处理」 | — |
| outcome = CANCELLED | 不变，危险色 | 「已取消」 | — |

## 5. 新动效的检查单

1. 这个动效回答了用户的哪个问题？答不出就不做（P1）。
2. 触发它的是哪个真实事件？写进 §4 的表（P2、P8）。
3. 哪个物体承接变化？避免「消失 + 出现」的硬切（P3）。
4. 同屏是否只有一个物体在变形？时长是否 ≤ 600ms（P4、§5）。
5. 降动画时信息是否完整？读屏能否读到（P7）。
6. 是否只用了 `@/components/kx` 与 `@/components/motion` 里的原语？新原语先进组件库再用。
