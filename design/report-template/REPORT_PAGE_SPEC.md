# 报告页通用规范（HTML 封装交付）

> 适用：Kern 及数字员工的一切「报告类输出」（新品评估、对标调研、立项报告……）
> 目标：用户要的不是一长串数据，而是一份**有结论、有证据、有来源、可打开、可转发**的报告页。
> 与现有体系的关系：本规范是 `design/report-template/README.md` 的上层统一；
> 「立项决策报告」（12 章节、三态标注）与「调研对标报告」（本规范 §2 的 B 型）是同一底座的两种投影。

## 0. 规范地图（一份总纲，三处分工）

| 文档 | 角色 | 管什么，不管什么 |
|------|------|------------------|
| 本规范（REPORT_PAGE_SPEC.md） | 总纲 | 管信息架构（六件套）、数据诚实三档、交付约束、Kern 接入方式；不管具体模板的区块细节 |
| `README.md` | A 型渲染手册 | 管决策层/执行层两份单文件 HTML 模板的区块、约束与示例；不管通用信息架构 |
| `src/modules/visual-intelligence/report-format.ts` | 内容契约（代码） | 管报告章节、字数预算、三态标注的数据结构；不管 HTML 怎么画 |

三层各管一层，互不重复：**内容层（章节数据）→ 渲染层（HTML 模板）→ 交付层（链接）**。
看报告页怎么做，先读本规范；写模板，看 README；改章节结构，改 report-format.ts。

## 1. 底层逻辑（一句话）

**结论先行 → 证据卡片 → 观点提炼 → 来源与未知。**
读者 30 秒能带走结论，3 分钟能扫完证据，需要时能下钻到每条数字的来源。
页面只回答一个问题，不塞第二个。

## 2. 信息架构（六件套）

| # | 区块 | 作用 | 规则 |
|---|------|------|------|
| 1 | 标题区 | 一句话说明这是什么报告 | 含数据日期；含数据口径声明（一句话） |
| 2 | 视角筛选器 | 让不同读者只看自己关心的 | 按读者任务切分（如 全部/头部/新锐）；不是装饰，没有两种以上读者就不做 |
| 3 | 证据卡片 | 承载全部事实 | 每张卡**固定同一套槽位**（见 §3），槽位缺失就标未知，不删槽位 |
| 4 | 综合观点 | 从证据中提炼的打法/判断 | 这是观点不是复述；条目化，每条一句话能单独转发 |
| 5 | 数据来源 | 每条关键数字的出处 | 链接或工具名；第三方的一律标注 |
| 6 | 未能核实 | 明确说哪些没核实 | 对应既有约束「缺失不留白」：写「已知什么 + 缺什么 + 如何补齐」 |

### A 型：评估类报告（新品评估、立项报告）

沿用现有 `report-template.example.html` 的 12 区块（结论摘要 → 验证计划与待决策），
本规范只追加两条：① 顶部加一句话标题区；② 末尾加「未能核实」区块。

### B 型：调研对标类报告（对标账号、竞品调研）

```
标题区（报告名 / 数据日期 / 口径声明）
视角筛选器（全部 / 分组A / 分组B …）
证据卡片 × N（每卡 6 槽位，见 §3）
综合观点（分组A抄什么 ×3 / 分组B抄什么 ×3）
数据来源（逐条）
未能核实（逐条：缺什么、如何补齐）
```

## 3. 证据卡片 6 槽位（B 型）

1. **身份**：名称 + 可点击链接（能链必链）
2. **规模证据**：订阅/播放/数量等硬数字
3. **内容形态**：画风、时长、频率等可复制的特征
4. **变现/结果**：怎么赚钱、什么结果
5. **可借鉴点**：1–2 条，只写「抄什么」
6. **来源标注**：每条数字后跟来源（见 §4）

## 4. 数据诚实三档（对应既有「三态标注」）

| 档位 | 含义 | 视觉 |
|------|------|------|
| 实地验证 | 当天亲手打开页面读到的数据 | 正常显示 |
| 第三方数据 | Social Blade / vidIQ 等工具估算 | 标注「第三方数据，仅供参考」 |
| 未能核实 | 没条件验证的 | 进「未能核实」区块，不混入正文 |

三档不单独依赖颜色区分（沿用既有无障碍约束）。

## 5. 交付约束

- **单文件**：CSS 内联，无外部 CSS / JS / 图表库依赖（沿用既有约束）。
- **交互只做筛选/折叠**：除筛选器、折叠、打印外不引入脚本；离线可读。
- **移动端可用**：390px 下卡片单列、筛选器可横滑，不挤压变形。
- **A4 打印友好**：`@media print` 下卡片不断裂（沿用既有约束）。
- **链接交付**：报告以可打开的链接交付，对话里只给 2–3 个 headline 数字 + 链接，
  不把全文粘进聊天。

## 6. Kern 输出 HTML 报告的接入方式（待立项）

报告内容仍由现有报告格式契约生成（如 `PRODUCT_DEVELOPMENT_REPORT` 的章节与字数预算），
本规范只约束**渲染层**：把「章节数据」映射到六件套 HTML。

- 内容层：沿用现有 `report-format.ts` 的章节契约（A 型）；
  B 型新增 `BENCHMARK_REPORT` 章节契约（卡片槽位 + 观点条目）。
- 渲染层：在 `design/report-template/` 下按 A / B 型各维护一份单文件 HTML 模板，
  数字由数据渲染，不手写进模板（沿用 README「数值应由产品数据渲染」）。
- 交付层：报告生成后落为可打开链接（应用内路由或静态文件二选一，见 OPEN_QUESTIONS），
  对话内只回 headline + 链接。
