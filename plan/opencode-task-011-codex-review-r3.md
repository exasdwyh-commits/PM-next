## R3 / HIGH：小容量和小批次仍永久遗漏组织

位置：`src/modules/worker/fair-queue.ts:73`、`:103`、`:107`；`src/modules/worker/loops.ts:192`；`src/modules/assistant-runtime/message-worker.ts:119`。

真实隔离库创建持续排队的组织，唯一合格策略在完成前补一条本组织任务。每轮实际执行后 drain，再开始下一轮，排除组织集合变化和未释放容量的干扰：

| 合法配置 | 轮数 | 实际获得执行的组织 |
|---|---:|---:|

原因有两处：

1. `markServed` 在预算获取前调用，总容量拒绝的组织也被当成服务过；小容量下形成固定步长跳过。

修复：总容量不足时保留当前候选的下一轮机会；组织容量不足可以跳过以寻找其他组织。服务位置始终记录实际推进到的组织；只有真正遍历到尾部才回绕。只读发现游标不能覆盖尚未服务的尾页位置。保持有界键集查询、组织内部排序和 scope。

## R1 / HIGH：存活排空进程仍能被时间阈值接管

位置：`src/modules/worker/index.ts:69`、`:151`～`:172`。

当前实现只在心跳年龄小于 LOCK_HUNG_MS 时拒绝存活 PID；超过 15 分钟即覆盖锁，没有先终止旧进程或撤销旧执行提交权。排空没有对应的强制撤权时限，所以把 60 秒改为 15 分钟并未建立所有权保证。

新增反例启动真实 Worker、真实锁及未释放的在途屏障，abort 使它停止准入并等待排空。仅将本次独立临时锁的 heartbeatAt 改为 16 分钟前，再用真实第二进程调用 acquireWorkerLock：**返回 ACQUIRED，旧持有者仍存活、在途屏障仍未释放。**

证据边界：只模拟锁文件年龄，没有实际等待 16 分钟；证明真实进程可以接管存活排空持有者，没有宣称重复模型调用已经发生。新进程仅测试锁获取，不启动任务或连接开发库。

修复推荐：本机不同 PID 仍存活时直接拒绝接管。需要处理卡死进程时，先确认旧进程终止，再取得锁；不要仅靠年龄判定旧执行已经失权。如选择撤权协议，必须证明所有旧执行无法继续提交，成本明显高于本机活进程保护。

验收：存活 PID + 过期时间 + 在途未结束时拒绝；死 PID 可接管；正常停止后可重新取得锁；文件心跳故障的原断言继续通过。

## R5 / MEDIUM：失败夹具的临时文件断言仍不完整

新最小夹具没有 HTTP 服务或真实 AgentTask；第 65 行只有端口检查注释，不能把专用夹具结果描述为验证 HTTP 端口/真实任务清理。夹具 300ms 等待也不可能跑过 10 秒文件心跳定时器。保留原公平回归对真实 HTTP 取消、长调用心跳及退出的覆盖，更新交付记录的证据边界。
