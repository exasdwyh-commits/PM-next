一句话：评审测试覆盖与质量风险：测了什么、没测什么、哪里最可能坏。

以下是方法纲要，按实际情况取舍，不必逐字执行。

## 什么时候用
要评估测试是否足够、或定位质量风险集中在哪。

## 做法
1. **列行为面**：这次改动影响了哪些行为（正常 / 边界 / 错误 / 权限 / 并发）。
2. **对照测试**：每个行为面有没有对应测试；没有的标为「未覆盖」。
3. **找高危区**：未覆盖 × 高影响 = 优先补的地方，按这个顺序排。
4. **看断言质量**：只断言「没抛错」的测试不算覆盖，标为「弱断言」。
5. **给补测计划**：最多 5 条，每条写清测什么、怎么算通过。

## 交付标准
- 行为面 × 覆盖矩阵 → 高危区 → 弱断言清单 → 补测计划。

## 红线
- 不得用行数覆盖率代替行为覆盖；
- 不得在没运行时写「全部通过」。
